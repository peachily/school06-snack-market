# 「얼마일까요?」 요구사항

## 1. 목적과 이번 단계의 범위

초등학생이 과자에 배정된 학습용 가격만큼 현금을 자릿값별로 옮겨 네 자리 수를 구성하고 읽는 활동이다. 교사가 전자칠판으로 학생들과 상호작용하며 숫자 읽기를 직접 안내한다. 실제 판매 가격은 사용하지 않는다.

이번 단계는 요구사항·아키텍처·타입·컴포넌트 책임·개발 순서·검증 기준을 문서로 확정하고 제공된 이미지를 배치하는 단계다. React 컴포넌트, 게임 로직, 실행 환경, 테스트는 아직 구현하지 않는다. README와 코드 주석은 작성하지 않는다.

## 2. 기술 범위

- React + TypeScript + Vite, Tailwind CSS v4
- pnpm workspace 경량 모노레포
- @dnd-kit/react, React Hooks 기반 상태 관리
- Vitest + React Testing Library
- Cloudflare Pages 정적 배포

Next.js, 백엔드, 데이터베이스, 인증, 별도 상태 관리 라이브러리, Turborepo를 사용하지 않는다. localStorage, sessionStorage 등 브라우저 영속 저장과 서버 저장을 사용하지 않는다.

## 3. 화면과 문구

가로 16:9 전자칠판을 우선한다. 넓고 단순한 화면에 상단, 중앙, 하단 지갑을 배치한다. 1920×1080과 1280×720을 우선 검증하며, 더 작은 화면에서도 핵심 조작을 잘라 숨기지 않는다.

### 상단

- 왼쪽 제목은 `얼마일까요?`다.
- 제목 아래 유일한 활동 안내는 `현금을 드래그해서 숫자를 채워 보세요.`다.
- 오른쪽에 `1`, `2`, `3` 탭을 표시하며 기본 선택은 `1`이다.
- 탭은 각각 서로 다른 학생 한 명과 해당 학생의 고정된 학습 수준을 의미한다.
- `수준`, `학생` 등 설명 라벨을 화면에 추가하지 않는다.
- 상단에 `다시 시작` 버튼을 배치한다.

### 중앙

- 과자 사진, 사진 아래 중앙 정렬한 과자 이름, 네 숫자 상자와 `원`을 표시한다.
- 문제 시작 시 숫자는 `0  0  0  0원`이다. 천의 자리도 0으로 시작한다.
- 숫자 상자에 `천`, `백`, `십`, `일` 라벨을 표시하지 않는다.
- 진행 중 네 상자는 충분한 간격을 유지한다. 각 배경·테두리 색상은 대응 지갑 영역과 같다.
- 목표 가격과 숫자 읽는 법은 화면, 제목 속성, 접근성 설명 등에 미리 노출하지 않는다. 지갑의 현금 수량으로 수를 구성한다.
- 완성한 뒤에만 사진 영역 오른쪽에 삼각형 다음 버튼을 표시한다. 마지막 문제에는 다음 버튼을 표시하지 않는다.

### 과자 사진 영역

제공된 배경 포함 원본 AVIF 30개를 그대로 사용한다. 배경 제거, 이미지 변환, 자동 크롭, 외부 다운로드, 임의 이미지 생성을 하지 않는다.

- 같은 화면 크기에서는 모든 사진에 동일한 고정 크기 영역을 사용한다.
- 흰색 또는 아주 연한 아이보리 배경, 부드러운 모서리, 아주 연한 베이지색 1px 테두리를 적용한다.
- 그림자는 없거나 매우 약하게 한다.
- 이미지에 `object-fit: contain`을 적용하고 원본 비율을 유지하여 전체가 잘리지 않게 표시한다.
- 영역 오른쪽의 다음 버튼 공간을 미리 확보해 버튼 출현으로 사진이나 이름이 밀리지 않게 한다.

### 지갑

- 하나의 큰 지갑 내부를 천·백·십·일 네 구역으로 나눈다.
- 상단에는 갈색 계열 가로 띠 한 줄로 입구를 표현한다.
- 내부 각 구역은 대응 파스텔색을 사용한다. 독립 카드나 개별 둥근 박스로 만들지 않는다.
- 구역 사이에는 세로 박음질 모양 구분선을 적용한다.
- 각 구역 상단에 `천`, `백`, `십`, `일` 라벨을 표시한다.
- 각 구역에는 고정된 3×3 슬롯 9개를 둔다. 현금은 겹치지 않는다.

## 4. 디자인 시스템

맑고 부드러운 파스텔톤의 작은 시장놀이 분위기를 유지한다. 다음 색상은 고정값이다.

| 자리 | 배경 | 테두리 및 포인트 |
| --- | --- | --- |
| 천 | #F8E1E3 | #E9A6AE |
| 백 | #DDEDF8 | #A2C9E8 |
| 십 | #E0F1E5 | #A5D5B9 |
| 일 | #FFF1CA | #F2D78D |

기본 글꼴은 Binggrae Regular/Bold다. 글꼴 파일은 현재 제공되지 않았으므로 구현 단계에서 사용 가능한 파일과 사용 조건을 확인한다. 확보 전에는 시스템 sans-serif로 임시 표시하고, 임의 파일 다운로드는 하지 않는다.

색상, 타이포그래피, 간격, 모서리, 그림자, 애니메이션 시간을 토큰으로 관리한다. 토큰 위치와 초기값은 ARCHITECTURE.md에 정의한다. 모션 감소 설정에서는 이동·흔들림·폭죽을 생략하거나 즉시 전환하되 완료 판정과 버튼 노출은 동일하다.

## 5. 출제 규칙

| 학생 탭 | 천 | 백 | 십 | 일 | 예시 |
| --- | --- | --- | --- | --- | --- |
| 1 | 1~9 | 0 | 0 | 0 | 3000, 7000 |
| 2 | 1~9 | 1~9 | 0 | 0 | 2400, 6800 |
| 3 | 1~9 | 0~9 | 0~9 | 0~9 | 1020, 5007, 8430 |

가격은 항상 1000~9999의 정수다. 각 허용 자리 숫자는 독립적으로 균등 추출한다. 과자 종류와 가격은 독립이며 가격 중복을 허용한다.

세 학생 각각 과자 30종을 한 번씩 학습한다. 각 학생의 순서를 별도로 셔플하며 학생 내 중복은 없다. 학생 간 같은 과자나 우연히 같은 순서가 나오는 것은 허용한다. 순서를 강제로 다르게 만들지 않는다.

첫 세션 생성 시 학생별로 30문제의 과자 순서와 가격을 준비한다. 다음 버튼과 탭 전환은 기존 문제를 사용하며 다시 무작위 생성하지 않는다. 초기 렌더링이나 재렌더링 횟수에 따라 출제가 바뀌어서는 안 된다.

## 6. 상태와 진행

학생마다 문제 목록, 현재 문제 인덱스, 목표 가격, 사용한 현금, 문제 완료 및 전체 완료 상태를 독립적으로 보유한다. 탭 전환은 선택 학생만 변경한다. 브라우저 새로고침과 페이지 재진입은 세 학생 모두 새로운 세션으로 시작한다.

- 문제는 진행 중 → 완성으로만 전환한다. 사용한 현금을 되돌리는 기능은 이번 범위에 없다.
- 완성 후 다음 버튼을 누르면 바로 다음 문제를 표시한다. 아직 완성하지 않았다면 다음으로 갈 수 없다.
- 30번째 문제의 마지막 현금을 올바르게 놓는 즉시 해당 학생의 전체 완료 상태가 된다.
- 마지막 완성 숫자와 과자 화면을 유지하고 추가 과자, 다음 버튼, 별도 완료 팝업이나 문구를 표시하지 않는다.
- 완료 후에도 다른 학생 탭과 다시 시작을 사용할 수 있다.
- 탭 복귀 시 완료 상태는 유지하되 폭죽을 다시 재생하지 않는다.

`다시 시작`은 현재 학생만 초기화한다. 확인창 문구는 `현재 활동을 처음부터 다시 시작할까요?`, 동작은 `취소`와 `다시 시작`으로 한다. 취소 시 상태를 유지하고, 확정 시 해당 학생의 순서·가격·사용 현금·완료 상태를 새로 만든 뒤 첫 문제로 이동한다. 다른 두 학생은 변경하지 않는다. 확인창이 열린 동안 배경 조작과 탭 전환을 막는다. 이는 초기화 확인용이며 정답 팝업과 별개다.

## 7. 현금과 슬롯

| 자리 | 액면가 | 이미지 |
| --- | --- | --- |
| 천 | 1,000원 지폐 | /images/cash/1000.webp |
| 백 | 100원 동전 | /images/cash/100.webp |
| 십 | 10원 동전 | /images/cash/10.webp |
| 일 | 1원 동전 | /images/cash/1.webp |

각 자리의 목표 숫자만큼만 현금을 표시한다. 0인 자리는 현금이 없으며 슬롯 구조는 유지한다. 현금 이미지는 제공된 배경 제거 WebP 원본을 사용한다.

각 구역은 왼쪽 위부터 행 우선으로 슬롯 0~8에 현금을 배치한다. 해당 문제 동안 현금의 식별자와 슬롯 인덱스는 고정된다. 사용된 현금의 슬롯은 빈자리로 남는다. 배열 필터링으로 슬롯을 압축하거나 나머지 현금을 이동·재정렬하지 않는다. 동일 자리의 어느 현금을 먼저 사용해도 결과가 같다.

## 8. 조작과 접근성

- 마우스, 터치, 키보드로 같은 상태 전이를 수행한다.
- 드래그 시 현금을 약 1.1배 확대한다. 원래 슬롯 크기는 유지하고 별도 시각 레이어로 이동시킨다.
- 올바른 자릿값 상자에 놓으면 해당 현금을 한 번 사용 처리하고 해당 숫자를 1 증가시킨다.
- 잘못된 상자는 짧은 좌우 흔들림 후 원래 슬롯로 복귀한다. 숫자와 사용 현금 상태는 바뀌지 않는다.
- 상자 밖 드롭이나 드래그 취소는 원래 슬롯로 복귀하며 상태를 바꾸지 않는다.
- 드롭 영역은 보이는 숫자 상자보다 조금 넓게 하되 이웃 영역과 겹치지 않게 한다. 경계의 빈 공간은 무효 드롭이다.
- 한 번에 현금 하나만 조작한다. 추가 손가락이나 중복 종료 이벤트가 이중 사용을 일으켜서는 안 된다.
- 드래그 도중 탭 전환, 초기화 확인 열기, 창 포커스 상실 시 드래그를 취소한다. 늦게 도착한 이전 문제의 이벤트는 무시한다.

키보드 대체 조작은 Tab으로 현금에 접근, Enter/Space로 선택, 좌우 방향키로 네 대상 상자 이동, Enter/Space로 놓기, Escape로 취소하는 흐름으로 설계한다. 선택 직후에는 해당 자릿값 상자를 대상으로 한다. 잘못된 대상으로 이동해 놓는 경우에도 동일한 오답 규칙을 따른다.

접근성 이름은 현금의 액면가, 대상 자릿값, 탭 번호, `다음`, `다시 시작`을 설명하되 목표 가격을 노출하지 않는다. 드롭 결과는 필요한 최소한의 비시각 상태 알림으로 제공하며 칭찬·읽는 법·정답 안내를 추가하지 않는다. 포커스 표시와 선택 상태를 색상 외의 형태로도 구분한다. 조작 대상은 최소 48×48 CSS px로 설계한다.

성공 후에는 같은 자리의 다음 미사용 현금으로 포커스를 이동한다. 없으면 다음 자리의 미사용 현금으로 이동하고, 모든 현금을 사용했다면 다음 버튼 또는 마지막 문제의 다시 시작 버튼으로 이동한다. 오답·취소 시 원래 현금으로 복귀한다. 확인창 닫힘과 문제 변경 뒤에도 포커스가 문서 본문으로 유실되지 않게 한다.

## 9. 완성 연출

완료 조건은 모든 현금이 올바른 자리에 사용된 것이다. 구성 숫자와 목표 숫자의 일치도 불변 조건으로 검증한다.

1. 떨어져 있던 네 숫자 상자가 중앙으로 이동하여 연결된 네 자리 수 형태를 이룬다. `원`은 수 오른쪽에 유지한다.
2. 주변에 연한 파스텔 색종이 폭죽을 잠깐 표시한다.
3. 마지막 문제가 아니라면 사진 오른쪽에 삼각형 다음 버튼을 표시한다.

정답 안내, 읽는 법, 칭찬 문장, 별도 팝업을 표시하지 않는다. 완료 상태는 연출 시작 전에 확정하고 후속 드롭을 차단한다. 다음 버튼은 연출 완료 뒤 노출하며 모션 감소 시 즉시 노출한다. 탭 전환 시 연출을 정리하고 돌아오면 완성 화면과 사용 가능한 다음 버튼을 표시한다.

## 10. 데이터 및 자산

과자 30개는 `apps/web/public/images/snacks/snack01.avif`부터 `snack30.avif`까지 배치한다. 화폐 4개는 `apps/web/public/images/cash/`에 배치한다. 파일명, 포맷, 이미지 바이트를 유지한다.

구현 단계에서 과자 목록과 이미지 경로는 `apps/web/src/data/snacks.ts`, 화폐 목록은 `apps/web/src/data/cash.ts`에서 관리한다. UI 컴포넌트에 목록과 경로를 하드코딩하지 않는다. 이번 단계에서는 데이터 파일도 구현하지 않는다.

파일명만으로 실제 과자 이름을 추정하지 않는다. 실제 이름 매핑은 구현 전에 사용자 제공 정보로 확정하며, 그 전에는 `과자 01`~`과자 30`을 중립적인 임시 이름으로 사용할 수 있다. 이미지가 없거나 로드에 실패하면 같은 크기의 중립적 텍스트·도형 플레이스홀더를 사용한다. 이미지 오류는 과자 제외, 문제 재추첨, 학습 진행 차단 사유가 아니다.
